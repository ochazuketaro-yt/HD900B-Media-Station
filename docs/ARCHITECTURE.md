# アーキテクチャ

```
PC のブラウザ ──HTTP :8820──┐
                            ▼
テレビ(Premium Apps RSS)─▶ hdms ─▶ /sys/block, /proc/mounts, mount(2)
  HIMEDIA_System("wget …/tv/do?c=…")      │      ├─ ジョブ(fork) ─▶ コピー → fsync → O_DIRECT 読み戻し → rename
  RSS: http://127.0.0.1:8820/tv/*.rss     │      └─ 状態: /tmp/ms/jobs/<id>.json(原子的更新)・.log・.cancel
                                          └─ 監視ループ(3 秒): 自動マウント、挿入検知→自動取り込み
```

- **単一の静的 MIPS バイナリ**(約 0.7 MB)。スレッドは使わず、接続ごと・ジョブごとに `fork`。ジョブの異常やカード抜去で Web サーバーが道連れにならない。
  設定は `/tmp/ms/config` を各プロセスが読み直す(親と子が別プロセスのため)。
- **ストレージ識別**: `/sys/block/<dev>` のリンク先で `sata_rtk`→HDD、`/usb`→USB、`mmc`→SD、`sr*`→DVD。内蔵フラッシュ(mtd*)は対象外で、API はボリューム ID(`hdd1`、`usb1`、`sd1`、`dvd1`)しか受け付けない。
- **パス安全性**: クライアントのパスは正規化(`..`・制御文字を拒否)後に `realpath` でボリューム内に収まることを検証。シンボリックリンクは一覧・コピーから除外。内部名(`.mediastation`、`*.mstmp`)は予約。
- **アクセス制限**: プライベートアドレス(127/8, 10/8, 172.16/12, 192.168/16, 169.254/16)以外は 403。変更系は `X-MS: 1` ヘッダ必須(他サイトからのフォーム送信対策)。ループバックはテレビ用に免除。任意の PIN(Basic 認証)。
- **コピーの確実性**: 一時名 `.name.mstmp` に書く → `fsync` → `O_DIRECT` で読み戻して XXH64(または SHA-256)比較 → `rename`。不一致なら一時ファイルを削除してエラー記録。
- **テレビ側**: 実機での実験どおり、純正 RSS の `onClick` から `HIMEDIA_System` で固定コマンドを実行し、`url=` で結果ページ(RSS)を開く。右側のリストは hdms が生成する RSS 2.0。進捗の自動更新は未実装。
- **永続化しない理由**: 起動時の自動実行には mtd1(SquashFS)の書換えまたは `/data` の恒久変更が必要で、失敗すると起動不能になり得る。このプロジェクトは `/tmp` と bind mount だけで完結する。
